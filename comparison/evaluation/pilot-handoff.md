# Independent pilot handoff

**Not yet run.** We need someone outside Tempus's implementation to author and adjudicate realistic tasks, and unfamiliar participants to attempt them. Current fixtures and scripted answers are development evidence. Do not use them as independent pilot tasks.

The [protocol](protocol.md) owns evaluation rules; [status](status.json) records missing people, access and decisions. This handoff supplies the practical next steps without freezing claims or opening holdouts.

## Before the session

- Assign an independent task author/evaluator and a second reviewer for ambiguous expected outcomes. Assign a separate holdout custodian before any later confirmatory study.
- Ask the evaluator to write realistic reminder, schedule and calculator goals, including ordinary requests and situations likely to expose Tempus's weaknesses. Record intended meaning and acceptable outcomes before showing either engine's output. Keep pilot data separate from hidden evaluation data.
- Choose participants unfamiliar with the implementation and record their device/browser. Agree on session length, assistance rules, timeouts and what counts as a correct usable result before the session. A rejected valid task, unanswered question or abandoned task remains incomplete.
- Record the exact app source, SDK archive, gpu-time version and integration used. The candidate record in the release checklist is a proposed baseline, not a frozen pair. Do not compare different interface quality without disclosing the difference and the caller-built work required.
- Obtain physical-device access separately from narrow desktop viewport testing. Calendar import requires explicit authorization and disposable calendars. Until then stop at file download/readback; do not describe it as an import task completed.

## Observe the whole task

Let the participant enter their own short English text, inspect the interpretation, make corrections and reach the usable output. Avoid teaching the accepted grammar or choosing answers for them. Record any help given rather than hiding it.

Record initial input and intended meaning, first interpretation, each clarification/edit, final output correctness, elapsed time, assistance, confusion, abandonment and remaining uncertainty. Capture only consented task data; do not collect personal calendar contents or secrets. Retain incorrect accepts and failures alongside successes.

Have the independent evaluator assess whether the final output fulfills the original task, including event text, complete intervals/recurrence, timezone and exclusions. File validation and client import are distinct stages. A successful download dialog is not proof of imported dates or recurrence.

## After the pilot

Report completed correct tasks and failures by user job, with denominators, assistance and device details. A Tempus-only session can identify usability failures; it cannot establish superiority over gpu-time. Comparative sessions need a declared integration for each product and the protocol's agreed assignment and analysis.

Use observed failures to prioritize work. Then agree on claims, budgets, sample allocation and analysis before freezing artifacts and commissioning untouched holdouts. Do not call the pilot a confirmatory result.

The smallest unblock is a named independent evaluator, unfamiliar participants and designated device access. Calendar-client work additionally needs explicit import authorization. This file authorizes no outreach, deployment, data collection or calendar write.
