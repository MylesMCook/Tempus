# Dogfood report — September 13, 2026

This black-box pass exercised the deployed playground, output formats, ambiguity and correction, recurrence, ranges, timezone and DST behavior, API boundaries, offline behavior, navigation, 320px layout, keyboard access and accessibility. It used more than 100 distinct phrases. A five-event calendar file also passed an independent iCalendar reader.

The pass found no confirmed critical or high-severity issues. It found nine medium issues and one low issue:

1. A one-occurrence schedule uses plural labels.
2. A horizontally scrollable code sample on the developer page cannot receive keyboard focus.
3. Common punctuation in event text can block an otherwise valid date expression.
4. Recurrence shorthand such as `Mondays at noon` can produce an unrelated arithmetic error.
5. Common range word orders and separators are rejected.
6. Timezones written inside the phrase are rejected or explained poorly.
7. Named and relative recurrence boundaries are rejected.
8. Some finite monthly schedules ask for a short-month policy they will never need.
9. Complete schedule preparation can fail offline when its Worker module was not loaded earlier; the error does not identify connectivity as the cause.
10. `from Friday to Monday` resolves both weekdays against one reference week and then rejects the reversed range.

The highest correctness priority is the cross-week range. The broadest usability problem is narrow natural-language coverage paired with recovery messages that describe the wrong input family. These findings are release backlog, not proof of general failure or a comparative ranking.

The test used desktop browser automation. A narrow viewport is not a physical-phone test. No calendar-client import, assistive-technology session or independent-user study was performed. Passing authored checks does not establish overall superiority over gpu-time.
